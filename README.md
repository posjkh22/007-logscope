# Logscope

여러 로그 파일을 한 번에 검색하고, 검색 결과에서 **전체 너비의 로그 뷰어 탭**으로 이동하는 **Electron + 순수 JavaScript 데스크톱 앱**입니다. Windows에서 개발·검증했습니다. 서버, 계정, API 키가 필요하지 않습니다.

## 실행

이미 빌드된 Windows 실행 파일: **[release/Logscope-1.2.0-portable.exe](release/Logscope-1.2.0-portable.exe)**. 설치 없이 실행할 수 있습니다.

개발 환경에서는 Node.js 22 이상을 설치한 후 실행합니다.

```powershell
npm ci
npm start
```

처음 실행하면 명확하게 표시된 샘플 워크스페이스에서 `timeout` 검색을 보여 줍니다. **폴더 가져오기** 또는 **파일 추가**로 실제 파일을 가져오면 샘플을 대체합니다. 이후 추가하는 실제 파일들은 기존 목록에 합쳐집니다. 마지막 실제 파일 목록은 다음 실행에서 복원되며, 비운 목록도 그대로 유지됩니다.

**폴더 가져오기는 워크스페이스 루트를 지정하거나 폴더를 계속 감시하는 기능이 아닙니다.** 가져오는 시점에 폴더와 하위 폴더의 로그 파일들을 찾아 현재 검색 목록에 합칩니다. 다른 폴더도 같은 목록에 합칠 수 있습니다. 새로 생성된 로그는 해당 폴더를 다시 가져와 추가하며, 이미 있는 파일은 중복으로 추가하지 않습니다.

파일 행에 항상 표시되는 **×**는 해당 파일만 목록에서 제거합니다. **선택 제거**는 검색 대상으로 체크한 파일들을 한 번에 제거합니다. **초기화**는 파일 목록·열린 탭·검색 결과·검색 조건을 비우며, 북마크와 저장한 검색은 유지합니다. 이 세 동작은 모두 원본 로그 파일을 삭제하거나 수정하지 않습니다. 초기화한 뒤 다시 실행해도 데모가 자동으로 채워지지 않으며, 하단 ‘샘플 로그 열기’로 직접 열 수 있습니다.

## 주요 기능

| 영역 | 기능 |
| --- | --- |
| 파일 가져오기 | 여러 파일·폴더 선택, 하위 폴더 재귀 탐색, 파일·폴더 드래그 앤 드롭, 중복 방지, 파일별 검색 포함 선택 |
| 통합 검색 | 문구·정규식, 대소문자 구분, 한글 포함 Unicode 단어 경계, AND/OR와 따옴표 문구, 제외 문구, glob 패턴 |
| 필터 | ERROR/WARN/INFO 빠른 필터, TRACE/DEBUG/FATAL/레벨 없는 행, 시작·종료 시간, 결과 상한, 인코딩 지정 |
| 작업 탭 | 통합 검색 / 로그 뷰어를 전체 너비로 전환, Ctrl+1 / Ctrl+2, 검색 결과·스크롤·열린 파일 유지, 간결한 검색 도구 모음 |
| 검색 결과 | 파일 이름과 전체 절대 경로 표시, 가상 스크롤, 매칭 하이라이트, 행 번호, 진행 상태, 즉시 중지, 파일순·시간 내림차순 정렬 |
| 로그 뷰어 | 원문의 앞뒤 문맥, 파일별 탭, 전체 파일 재검색과 이전·다음 일치, 일치 행만 표시, 원문 행 이동, 이전·다음 구간 |
| 뷰어 하단 검색 목록 | 파일 전체의 일치 행·시간·레벨·내용, 클릭한 행의 원문으로 이동, 문구/OR/AND 검색 방식, 레벨·제외 문구·대소문자·정규식 조건, 결과 복사, 패널 접기·높이 조절, 레벨별 집계 |
| 로그 읽기 | UTF-8·CP949/EUC-KR·UTF-16LE, 색상으로 레벨 구분, 줄바꿈, 글자 크기, 여러 키워드의 컬러 하이라이트 |
| 조사 도구 | trace_id/request_id 또는 선택한 텍스트로 전체 파일 ID 추적, 행 북마크, JSON 자동 포맷/행 상세 보기, 현재 행·전체 파일 경로 복사, 탐색기에서 열기, 선택한 텍스트 더블클릭 검색 |
| 반복 작업 | 필터까지 저장하는 검색, 최근 검색 20개, 명령 팔레트, 키보드 단축키, 하단 검색 목록 높이 저장 |
| LIVE | 1.5초 간격으로 파일 끝 추적, 추가된 구간의 인덱스 갱신, 파일 축소·교체 감지 |
| 내보내기 | 현재 통합 검색 결과 전체를 UTF-8 BOM CSV 또는 JSON으로 저장, CSV 수식 주입 방지 |

폴더 탐색 대상 확장자는 `.log`, `.txt`, `.jsonl`, `.ndjson`, `.out`, `.err`, `.trace`, `.csv`, `.json`입니다. 파일을 직접 선택할 때는 모든 확장자를 열 수 있습니다. 심볼릭 링크와 `node_modules`, `.git` 등은 재귀 탐색에서 건너뜁니다.

## 사용 흐름

1. 왼쪽에서 폴더 또는 로그 파일을 추가하고 검색할 파일을 체크합니다.
2. 상단 검색창에서 검색합니다. 빈 검색어는 필터에 해당하는 모든 행을 찾습니다.
3. 결과에서 파일 이름과 **전체 경로**를 확인하고 클릭하면 로그 뷰어 탭으로 전환되어 해당 행과 주변 원문을 넓게 보여 줍니다. Ctrl+1 또는 통합 검색 탭으로 돌아가면 결과와 스크롤 위치가 유지됩니다.
4. 뷰어 검색창은 **열려 있는 파일 전체**를 검색합니다. 하단에 일치 목록이 나타나고, 목록을 클릭하면 해당 행의 원문으로 이동합니다. F3/Shift+F3로도 이동할 수 있습니다.
5. 하단 목록에서 레벨·제외 문구를 바꾸거나 상단의 대소문자·정규식 조건을 적용합니다. 구분선을 드래그하거나 방향키로 높이를 바꾸고, ‘하단 검색 결과’로 접고 펼칩니다.
6. 현재 행의 `trace_id`, `request_id`, `correlation_id` 또는 직접 선택한 텍스트를 **ID 추적**으로 통합 검색합니다. 현재 선택한 파일 범위가 적용됩니다.
7. 중요 행은 Ctrl+B로 저장하고, 계속 기록되는 로그는 LIVE를 켭니다.

AND/OR 모드에서는 `connection timeout`으로 단어 조합을 찾고, `"connection pool" timeout`처럼 따옴표로 문구를 묶을 수 있습니다. 제외 문구와 파일 패턴은 쉼표로 나눕니다. 예: `healthcheck, heartbeat`, `*.log, **/server/*.txt`.

## 뷰어에서 여러 조건으로 검색하기

로그 뷰어 검색창 왼쪽에서 **하나 이상 (OR)**을 선택하고 `timeout "connection refused" failed`를 입력하세요. 세 조건 중 하나라도 포함된 행을 파일 전체에서 찾습니다. 같은 행에 여러 조건이 있어도 결과에는 한 번만 표시하며, 일치한 조건들을 하이라이트합니다. 조건은 두 개 이상 계속 추가할 수 있고 공백으로 구분합니다. `OR`라는 단어를 사이에 입력할 필요는 없습니다.

| 검색 방식 | 입력 예 | 동작 |
| --- | --- | --- |
| 하나 이상 (OR) | `timeout "connection refused" failed` | 세 조건 중 하나 이상 포함 |
| 모두 포함 (AND) | `payment timeout` | 같은 행에 두 조건 모두 포함 |
| 문구 그대로 | `payment timeout` | 공백까지 포함해 문구 그대로 일치 |
| 정규식 (`.*`) | `timeout|connection\s+refused|failed` | JavaScript 정규식의 대안 패턴으로 일치 |

OR/AND의 각 조건은 일반 텍스트입니다. `conn[42]` 같은 값의 기호도 그대로 검색합니다. 공백이 있는 문구는 큰따옴표로 묶고, 문구 안의 큰따옴표는 `\"`로 입력할 수 있습니다. 닫히지 않은 따옴표는 오류로 안내하고, 빈 따옴표는 조건으로 취급하지 않습니다. OR/AND는 레벨·제외 문구·대소문자 조건과 함께 적용됩니다. 정규식을 켜면 방식 선택에 ‘정규식’이 표시되며, `.*`를 해제하면 이전 OR/AND/문구 방식으로 돌아옵니다.

## 대용량 처리와 동작 범위

- 파일 전체를 메모리에 올리지 않고 128KB 스트림으로 읽습니다. 검색과 행 인덱싱은 별도의 Worker에서 실행합니다.
- 뷰어는 512행마다 저장한 바이트 위치로 이동한 뒤 약 300행을 읽습니다. 최초 인덱스 생성에는 파일 크기에 비례한 시간이 걸립니다.
- LIVE에서는 기존 파일의 식별자와 끝부분을 확인해 이어쓰기 구간을 다시 인덱싱합니다. 축소·교체된 파일은 전체 인덱스를 다시 만듭니다. 파일 중간을 편집하는 용도보다 계속 추가되는 로그에 적합합니다.
- 한 작업 공간은 최대 10,000개 파일, 통합 검색은 기본 20,000건/최대 100,000건 또는 결과 데이터 약 32MB에서 멈춥니다. 상한에 도달하면 안내합니다. 내보내기는 수집된 결과 범위입니다.
- 비정상적으로 긴 한 행은 앞부분 **256KB까지만 검색**하며 잘린 행 수를 안내합니다. 한 행의 화면 표시는 14,000자까지이며 복사·내보내기는 수집한 원문을 사용합니다.
- 파일 내 검색도 최대 20,000건/약 32MB입니다. 일치 행만 표시하면서 줄바꿈을 켜면 300개씩 나누어 표시하며 하단 화살표로 이동합니다.
- 정규식은 JavaScript 문법입니다. 30초 동안 검색 작업의 진행 응답이 없으면 작업을 종료합니다. UI의 중지 버튼은 Worker를 즉시 종료합니다.
- 자동 인코딩은 첫 8KB와 BOM을 사용한 휴리스틱입니다. 뒤쪽에서만 한글이 등장하는 CP949 파일 등은 상세 필터에서 인코딩을 직접 지정하세요. UTF-16BE, 압축 로그와 바이너리는 지원하지 않습니다.
- 시간 필터는 `YYYY-MM-DD HH:mm:ss` 또는 ISO 타임스탬프를 읽습니다. 시간대가 없는 값은 컴퓨터의 로컬 시간으로 해석하며, 시간 필터가 켜져 있으면 타임스탬프가 없는 스택 행은 제외합니다.
- 레벨 필터는 물리적인 한 행 단위입니다. `WARNING`은 `WARN`, `CRITICAL`은 `FATAL`로 정규화합니다. 여러 줄로 나뉜 예외는 원문 뷰어에서 앞뒤 문맥으로 확인합니다.
- LIVE는 열려 있는 파일 끝을 갱신합니다. 통합 검색 결과와 새로 생성된 파일 목록은 다시 검색하거나 폴더를 다시 추가해 갱신하세요.

## 검증 및 빌드

```powershell
npm run check       # JavaScript 구문 검사
npm test            # 스트리밍·인코딩·필터·정규식·Worker·대용량 인덱스 테스트
npm run test:e2e    # 실제 Electron 앱을 숨김 실행해 화면 및 IPC 검증
npm run dist        # Windows portable 실행 파일 생성
npm run test:package # 패키징된 app.asar의 실행·검색·원문 이동 확인
```

테스트는 OS 임시 폴더와 별도 사용자 프로필을 사용합니다. E2E 화면은 `test-results/logscope-desktop.png`에 기록됩니다.

```text
app/
  main.cjs                 파일 접근, IPC, 작업 관리, 내보내기
  preload.cjs              제한된 contextBridge API
  core.cjs                 스트리밍 리더, 메타데이터, 검색 조건
  worker.cjs               통합/파일 검색, 희소 행 인덱스
  renderer/                HTML, CSS, 순수 JavaScript UI
examples/                  실제로 읽고 검색하는 샘플 로그 3개
scripts/                   구문 검사, 샘플·아이콘 생성
tests/                     Node 테스트와 Electron E2E
```

Electron 45.0.0, iconv-lite 0.7.3을 사용합니다. 렌더러는 `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`로 실행하고 제한된 IPC만 노출합니다. CSP는 외부 연결과 스크립트를 차단하며 로그는 HTML로 실행되지 않도록 이스케이프합니다. 구현 시 [Electron 보안 가이드](https://www.electronjs.org/docs/latest/tutorial/security/)와 [webUtils 문서](https://www.electronjs.org/docs/latest/api/web-utils)를 확인했습니다.

워크스페이스 목록, 북마크, 검색 기록과 화면 설정은 Electron 사용자 데이터 디렉터리(Windows 기본값 `%APPDATA%/logscope`)에 로컬로 저장됩니다. 현재 실행 파일은 코드 서명을 적용하지 않았습니다. macOS/Linux 패키지는 이 환경에서 빌드·검증하지 않았습니다.
